## Identity headers (demo mode)

Every endpoint below is scoped to a caller identity, currently asserted
via headers (see `docs/SECURITY.md` for why this is demo-only):

```
X-Demo-Account-Type: employee | administrator
X-Demo-Employee-Id:  <employee id>   # only when account_type=employee
```

## Errors

Every error follows the same envelope:

```json
{
  "error": {
    "code": "FORBIDDEN",
    "message": "You are not authorized to view this employee's data.",
    "request_id": "a1b2c3d4e5f6"
  }
}
```

Common codes: `FORBIDDEN` (403), `*_NOT_FOUND` (404, e.g.
`EMPLOYEE_NOT_FOUND`), `BAD_REQUEST` (400), `INTERNAL_ERROR` (500 —
message is always generic; details are logged server-side only).

## Pagination / filtering

The current mock dataset is small enough that list endpoints return
everything the caller is authorized to see in one response (filtering is
done client-side for now — e.g. the Communication page's tabs and search).
`docs/ARCHITECTURE.md` and `backend/README.md` note this as a follow-up
once real Microsoft Graph data volumes are involved.
